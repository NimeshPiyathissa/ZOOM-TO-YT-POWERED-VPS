              ┌────────────▼────────────┐        user "dashboard"

   ┌───────────────────────▼──────────────────────────────────────────┐  user "zoombot"

   │                                                                  │
   │  xvfb ──► openbox ──► producer ─────────────┐                     │
   │  virtual    window      zoom (Linux client)  │ picture: X display │

## Pieces

| Component | What it does |
|---|---|
| `xvfb` | A virtual 1280x720 (or 1920x1080) screen with no monitor |
| `openbox` | Minimal window manager so Zoom/Chrome windows can be placed and maximised |
| `audio-setup` | PipeWire with a null sink `zoom_out`; the producer plays into it, FFmpeg records its monitor |
| `zoom` | The Zoom Linux client, joined through a `zoommtg://` deep link |
| `browser-source` | Google Chrome in kiosk mode for web pages, YouTube videos, or Zoom's web client |
| `ffmpeg-stream` | Captures the screen and sound (or reads a direct URL), applies framing and watermark, encodes H.264/AAC, sends to YouTube. **Only started by an authorised Go Live**; it has no auto-restart and no boot start |
| `x11vnc` + `novnc-proxy` | Remote view of the screen, loopback only, reached through the dashboard's authenticated websocket proxy |
| Dashboard | FastAPI app: pages, API, scheduler, watchdog, Telegram, recordings |
| Caddy | HTTPS in front of the dashboard |

## Two users, one narrow bridge

The pipeline runs as `zoombot`, the web app as `dashboard`. The dashboard can do only what
`/etc/sudoers.d/dashboard` lists: start/stop/restart/show specific units, and run specific scripts with
validated arguments. It cannot run a shell as `zoombot`. The file is generated by `dashboard/install-dashboard.sh`
and validated with `visudo` before it is installed.

## How Go Live works

1. The operator presses Go Live; the dashboard collects warnings (no stream key, Zoom not in a meeting, ...) and
   shows them.
2. On confirmation, the dashboard mints a **single-use grant** that expires in 60 seconds and writes a matching
   one-time permission into `current-source.env`.
3. `ffmpeg-stream` starts; `stream.sh` refuses to send anything without a valid, unused permission.
4. Stop is always allowed. Schedules, watchdogs and source switches can prepare everything, but cannot start the
   encoder.

## Data

SQLite (`/home/dashboard/data/dashboard.db`) holds users (argon2 hashes), sessions, login attempts, sources, schedules,
the audit log and settings. See [configuration.md](configuration.md) for every file and [encryption.md](encryption.md)
for secrets.
