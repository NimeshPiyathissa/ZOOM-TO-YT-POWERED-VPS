# Configuration reference

Almost everything is changed from the dashboard. This page lists where settings live, for when you need to look
under the hood.

## Where things are

| Path | Owner / mode | Contents |
|---|---|---|
| `/opt/zoom-stream` | root | The git clone the installer and `update.sh` work from |
| `/home/zoombot/zoom-stream/.env` | zoombot, 600 | Stream settings: YouTube key and ingest URL, resolution, FPS, bitrates, encoder preset, bot name. See [`.env.example`](../.env.example) |
| `/home/zoombot/zoom-stream/current-source.env` | zoombot | The active source and its framing/watermark settings. Written by the dashboard only |
| `/home/zoombot/zoom-stream/scripts/` | zoombot | Deployed pipeline scripts (copied from the clone) |
| `/home/zoombot/zoom-stream/logs/` | zoombot | `ffmpeg.log`, `zoom.log`, `browser.log`, recordings of tests |
| `/home/zoombot/.config/chrome-profiles/` | zoombot, 700 | Chrome profiles of your Google accounts |
| `/home/dashboard/app/` | dashboard | Deployed dashboard code and `settings.json` |
| `/home/dashboard/data/` | dashboard, 700 | `dashboard.db` (users, sources, schedules, audit log), `secrets.enc.json` (encrypted store), `overlay.json` |
| `/home/dashboard/recordings/` | dashboard | Program recordings |
| `/etc/zoom-stream/master.key` | root:dashboard, 640 | Cached key that unlocks the encrypted store at boot ([encryption.md](encryption.md)) |
| `/etc/zoom-stream/install.conf` | root | Installed version, source folder, domain |
| `/etc/caddy/Caddyfile` | root | HTTPS configuration (generated by `scripts/setup-https.sh`) |
| `/etc/sudoers.d/dashboard` | root, 440 | The commands the dashboard may run as `zoombot` ([security.md](security.md)) |
| `/var/log/zoom-stream/` | root, 700 | Installer and updater logs |
| `/var/backups/zoom-stream/` | root, 700 | Backups |

## Stream settings (`.env`)

| Key | Meaning | Changed on |
|---|---|---|
| `YT_STREAM_KEY` | YouTube stream key (secret) | Live Studio / Settings |
| `YT_RTMP_URL` | Ingest server without the key; empty = `rtmps://a.rtmps.youtube.com:443/live2` | edit `.env` |
| `RESOLUTION`, `FPS` | Encoded size and frame rate | Output |
| `VIDEO_BITRATE`, `AUDIO_BITRATE` | kbps (video 1000-8000) | Output |
| `X264_PRESET` | `ultrafast` … `medium`; faster = less CPU | Output |
| `BOT_NAME` | Name shown in Zoom | Settings |
| `ZOOM_SIGNIN_MODE` | `guest` or `google` | Zoom / Settings |
| `DISPLAY_NUM`, `DISPLAY_SIZE` | Virtual screen (advanced) | edit `.env` |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Notifications (token is secret) | Settings |

Editing by hand:

```bash
sudo -u zoombot nano /home/zoombot/zoom-stream/.env
```

Values are parsed, never executed. A change takes effect when the affected service next starts (stop and Go Live
again for encoder settings).

## Dashboard environment

Set with `sudo systemctl edit dashboard`:

```ini
[Service]
Environment=SCHEDULE_TIMEZONE=Europe/London
```

| Variable | Meaning |
|---|---|
| `SCHEDULE_TIMEZONE` | Timezone of the Schedule page if it should differ from the server timezone (default: the server timezone) |

## Server timezone

```bash
sudo timedatectl set-timezone Europe/London
sudo systemctl restart dashboard
```

## HTTPS

Add, change or remove the domain with `set-domain.sh` - it checks DNS and ports, configures Caddy, waits for the
certificate, verifies HTTPS and records the choice in `/etc/zoom-stream/install.conf` (used by `doctor.sh`):

```bash
sudo bash /opt/zoom-stream/set-domain.sh stream.example.com --email you@example.com   # Let's Encrypt (auto-renewed)
sudo bash /opt/zoom-stream/set-domain.sh stream.example.com --staging                 # test certificates
sudo bash /opt/zoom-stream/set-domain.sh --none                                       # IP only, self-signed
sudo bash /opt/zoom-stream/set-domain.sh --check                                      # re-check everything
```

It calls `scripts/setup-https.sh`, which writes `/etc/caddy/Caddyfile`, validates it with Caddy before installing it
and keeps a backup of the previous file. Only Caddy is reloaded. Step-by-step guide:
[Subdomain, DNS and HTTPS](domain-and-https.md).

## Admin password

```bash
cd /home/dashboard/app
sudo -u dashboard /home/dashboard/venv/bin/python -m app.cli set-password admin        # asks twice
printf '%s\n' "$NEW_PASSWORD" | sudo -u dashboard /home/dashboard/venv/bin/python -m app.cli set-password admin --password-stdin
```

Changing the password signs out every open session of that user. Five failed sign-ins from the same address lock
that username out for 15 minutes; a successful sign-in clears the failure count.

## VNC password

Rotate it from the dashboard (Settings or Remote GUI). The new password is stored in the encrypted store.
