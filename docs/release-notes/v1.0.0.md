# Zoom to YouTube Live Streaming v1.0.0

**DRAFT - the "Tested environment" section is completed after the test-server run.**

The first public release: stream a Zoom meeting, a web page or a media feed to YouTube Live from your own Ubuntu
server, controlled from a web dashboard, installed with one guided command.

## Highlights

- **One-command guided installer** for Ubuntu 24.04 - checks the server, asks a few validated questions, shows a
  summary, installs everything from official sources, and resumes automatically if something fails.
- **Nothing goes on air by itself** - every broadcast needs a confirmed Go Live.
- **Clean meeting picture** - hide Zoom's toolbars, Fit/Fill/Auto framing with measured border detection.
- **Subdomain + trusted HTTPS, guided** - the wizard shows the server's public IP and the exact DNS A record to
  create, checks public DNS with wait-and-retry, configures Caddy with an automatically renewed Let's Encrypt
  certificate and verifies HTTPS at the end. IP-only mode remains available with a clear warning.
- **Safe operations** - updates with automatic rollback, verified backups, and a doctor that explains problems.

## Features

- Sources: Zoom (desktop client or web client, guest or Google sign-in, invitation parsing), web pages in a Chrome
  kiosk, direct media URLs (HLS/RTMP/RTMPS/SRT/file).
- Live Studio: telemetry, audio meter, test recording, program recording, YouTube live chat.
- Output page: Auto/Fit/Fill framing and quality presets (720p / 1080p).
- Watermark Studio: text or logo burned in by the encoder, 66 open-licence fonts.
- Schedules: join early, stop and leave at the end (going live stays manual).
- Remote GUI (noVNC through the dashboard login), Google account profiles with session checks.
- Redacted live logs, audit log, Telegram notifications, daily disk clean-up, service watchdog.
- HTTPS via Caddy (Let's Encrypt or self-signed), argon2 passwords, login lockout, CSRF protection, encrypted store
  for the VNC password, narrow sudo allowlist.

## Subdomain, DNS and HTTPS

- Wizard: asks for the (sub)domain, shows this server's public IP (or asks for it if it cannot be detected) and the
  exact A record (`Name`/`Value`) for your DNS provider.
- DNS check against public resolvers, explaining a missing record, a wrong IP, a Cloudflare proxy (orange cloud),
  extra A records and an IPv6 record elsewhere; `w` waits and re-checks for up to 10 minutes.
- Caddy reverse proxy with automatic HTTPS: Let's Encrypt certificate, automatic renewal, http→https redirect.
- After installation: ufw + reachability check of ports 80/443, waits for the certificate, loads the site over HTTPS,
  and explains DNS, port, rate-limit and CAA errors in plain words.
- `--staging` (installer and `set-domain.sh`, or `LE_STAGING=yes`) uses Let's Encrypt's staging service for repeated
  test installs.
- IP-only mode (`none`) with a clear "not browser-trusted" warning.
- New `set-domain.sh` adds, changes or removes the domain later (`--none`, `--check`); it only reloads Caddy.
- `doctor.sh` uses the same DNS/port/certificate checks and reports staging certificates.
- Beginner guide: [Subdomain, DNS and HTTPS](../domain-and-https.md), including DNS/SSL troubleshooting.

## Improvements

- Configurable ingest URL and schedule timezone; non-interactive admin password setup.
- `update.sh`, `backup.sh`, `restore.sh`, `uninstall.sh`, `doctor.sh`.
- shellcheck-clean scripts, CI on Ubuntu 24.04 / Python 3.12.

## Bug fixes

- A successful sign-in no longer deletes successful login records - only failed attempts are cleared.
- `app.cli set-password` now resets the admin password instead of creating a user named `set-password`.
- Fresh-server HTTPS setup is no longer blocked by Ubuntu's default Caddyfile.
- The installer waits for the apt lock instead of failing during automatic updates.
- `doctor.sh` no longer skips the "firewall blocks HTTPS" result (a stray line continuation swallowed it).

## Known issues and limitations

- **Not yet verified in a real live class.** The installer, dashboard and pipeline were tested on a fresh Ubuntu 24.04
  server without a real Zoom meeting and without streaming to YouTube (only local test recordings). Joining a real
  meeting, audio/video sync over a long session, and YouTube ingest health are unverified for this release - please
  run the [first live test checklist](../first-live-test.md) before relying on it.
- **1080p** is not verified on 4 vCPU with a real meeting; 720p is the recommended default.
- The YouTube stream key, Zoom passcodes and Telegram token are protected by file permissions, not encrypted at rest
  (only the VNC password is in the encrypted store).
- Switching sources while live causes a short reconnect on YouTube, not a seamless cut.
- Zoom's Linux client changes its interface between versions; toolbar hiding and status detection may need updates
  after a Zoom update.
- Only YouTube is tested as a destination.
- Only IPv4 is configured by the wizard (A record). An AAAA record pointing elsewhere is detected and must be removed.
- Let's Encrypt rate limits apply to real certificates (5 identical certificates per week); use `--staging` for tests.
