# Zoom to YouTube Live Streaming v1.0.2

An audit release. The public installer was compared item by item with a working production server, reviewed for
fragile assumptions, and tested again on a real Ubuntu 24.04 server in both modes (domain with Let's Encrypt staging
certificates, and IP address only). The streaming pipeline itself is unchanged: with the same settings, the encoder
command line is identical to the production server's.

## Fixes

- **No SSH lock-out.** The firewall step now allows the port(s) your SSH server really listens on before it turns
  ufw on. Earlier versions allowed only port 22.
- **`update.sh` never goes backwards on its own.** An install made from the `main` branch is no longer "updated" to
  an older release tag. Moving to an older version on purpose still works with `--ref`.
- **Re-running the one-command installer** on an unfinished install now really installs the version you asked for,
  and refuses to touch a `/opt/zoom-stream` folder that is not this project.
- **`rsync` is installed** (Chrome account backup and import need it).
- **Servers set to another language** (German, French ...) are handled: the installer reads tool output in English.
- **`uninstall.sh`** ends with a clear success status, names the line if something unexpected fails, removes the
  service accounts reliably and tells you if one could not be removed.
- **Output page:** when you pick an output larger than the bot's virtual screen (for example 1080p on a default
  720p install), it now tells you the picture is only enlarged. `docs/configuration.md` ("Virtual screen size")
  explains how to get a true 1080p screen.

## Changes

- **Caddy comes from Caddy's own apt repository** (current stable release, the signing key's fingerprint is checked)
  instead of the 2022 version in Ubuntu 24.04. If that repository cannot be reached, Ubuntu's package is used as
  before. Updating an existing install upgrades Caddy in place; your Caddyfile and certificates are kept. HTTPS is
  interrupted for a few seconds while Caddy restarts.
- **Python packages are fully pinned** (`dashboard/constraints.txt`): every install gets the same tested set.
- CI actions updated (no more Node 20 deprecation warning).

## Upgrading

```bash
sudo /opt/zoom-stream/update.sh
```

`update.sh` refuses to run during a broadcast, takes a backup first and rolls back automatically if anything fails.

A fresh install uses the same one command as before:

```bash
curl -fsSL https://raw.githubusercontent.com/NimeshPiyathissa/ZOOM-TO-YT-POWERED-VPS/main/install.sh -o install.sh
sudo bash install.sh
```

## Known issues

Unchanged from [v1.0.0](v1.0.0.md#known-issues-and-limitations), plus:

- The `uninstall.sh` exit status 1 seen once during v1.0.0 testing was not reproduced in this audit either (three
  further runs, including after the same install / update / domain-change sequence, all ended with status 0). The
  script now reports the failing line if it ever happens again.
- Zoom and Google Chrome are always installed in their newest versions from their publishers. A new Zoom release
  can change its window layout; the installed versions are recorded in `/etc/zoom-stream/installer/versions.txt`.
- Not verified without a real meeting: joining, meeting detection and the "Meeting only" view against the current
  Zoom client, and 1080p CPU load with a live meeting on 4 CPU cores.
