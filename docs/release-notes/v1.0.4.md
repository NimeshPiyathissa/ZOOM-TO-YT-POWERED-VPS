# Zoom to YouTube Live Streaming v1.0.4

A bug-fix release. It makes a wrong stream key impossible to miss, makes framing choices reach the encoder, and fixes
two more places that captured the wrong screen size.

## Fixes

- **Go Live failed with "Job for ffmpeg-stream.service failed because the control process exited with error code"**,
  often with "sudo: unable to send audit message" above it, and "Restart All Services" seemed to fix it. It did not.
  The real cause was the stream key: a Zoom meeting link copied from the browser (ending in `#success`) had been saved
  in the stream-key field. The encoder sent it to YouTube as the key, YouTube closed the connection, and after five
  tries in five minutes systemd refused further starts with that misleading message. Saving the right key is what
  fixed it.

  Now:
  - Live Studio and Settings refuse a link, or a value with spaces, `/` or `#`, as a stream key and say why ("That is
    a Zoom meeting link, not a YouTube stream key").
  - If such a key was saved before this version, Go Live is blocked with a clear message instead of failing.
  - The encoder itself refuses it before connecting to YouTube.
  - When YouTube closes the connection anyway, the error says so and points at the stream key.
  - A confirmed Go Live clears systemd's start limit first, so the next try after fixing the key just works.
  - The sudo audit line is a harmless warning (the dashboard service is not allowed to write audit records) and is no
    longer shown with errors.

- **A framing choice made while framing was off never reached the encoder.** In Live Studio (and Remote GUI), picking
  "Fill 16:9" or a background such as "Blurred picture" before switching Clean Broadcast on was only remembered: the
  panel showed it as selected and the stream showed the whole screen. Choosing now switches framing on, the panel says
  "Off - the stream shows the whole screen" while it is off, and the Output page only shows what the server saved.

- **The audio self-test and the local recorder failed with "Error opening input files: Invalid argument"** when the
  output was larger than the screen (the same fault v1.0.3 fixed for the broadcast). Both now capture the real screen.

## Upgrading

```bash
sudo /opt/zoom-stream/update.sh
```

`update.sh` refuses to run during a broadcast, takes a backup first and rolls back automatically if anything fails.
Running streams, Zoom and Chrome are not restarted; only the dashboard is. If your saved stream key is not a valid
key, the Go Live dialog will now tell you - paste the key from YouTube Studio (Go live > Stream key) in Live Studio.

## Tested

On a test server: the update itself (only the changed files were touched), saving a Zoom link as the key (refused),
a bad key already saved (Go Live blocked, nothing started), the encoder script with a bad key (refused before
connecting), systemd's start limit on a separate test service (reproduced the exact message; cleared by Go Live's
reset), and a real Go Live to an unlisted YouTube stream with the correct key, without "Restart All Services".

## Known issues

- The Fill 16:9 / Blurred picture fix is covered by automated tests but has not yet been confirmed in a live meeting.
- **With the default 1280x720 virtual screen, a 1080p output is upscaled** (see "Virtual screen size" in
  `docs/configuration.md`).

Everything listed for [v1.0.2](v1.0.2.md#known-issues) also still applies.
